SUMMARY
================================================================================

PERFORMANCE (avg cycles)
------------------------
  -Og is SLOWER than -Os in every single one of 45 measurements
  (5 modes x 3 security levels x 3 operations).

  Slowdown range : +8.79% .. +28.37%
  Mean slowdown  : ~17.8%

  Smallest gap   : STACK / ML-KEM-1024 / Keypair        ( +8.79% )
  Largest gap    : STACK_DUALCORE / ML-KEM-512 / Decap  ( +28.37% )

  Per-mode mean slowdown of -Og vs -Os:
    SPEED            : +17.3%
    SPEED_DUALCORE   : +14.9%
    STACK_XTREME     : +19.1%
    STACK            : +15.8%
    STACK_DUALCORE   : +21.7%


STACKMAX (peak stack, bytes)
----------------------------
  Differences are small in absolute and relative terms; the compiler
  flag has only a marginal effect on stack-frame size.

  In the SPEED and SPEED_DUALCORE modes -Og uses very slightly LESS
  stack (typically -0.3% .. -1.3%). In STACK_XTREME the picture is
  mixed (a few +3..+7% outliers). In STACK / STACK_DUALCORE -Og also
  uses slightly less stack on average.

  Largest single deviations:
    -8.81%   STACK         / ML-KEM-512  / Keypair   (-Og uses less)
    +6.90%   STACK_XTREME  / ML-KEM-512  / Keypair   (-Og uses more)

  Otherwise all stackmax deltas are within +/- 3.5%.


CONCLUSION
----------
  -Os is the clear winner for runtime on this ESP32 build: ~18% faster
  on average across all configurations, with essentially equivalent
  stack usage (within a few percent, mostly under 2%). For thesis-grade
  performance numbers, -Os is the appropriate compiler flag; -Og should
  only be used when debug-friendly code is needed.
